# Step 1 · Router — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Obiettivo:** un nodo router LLM prima dell'agente: le domande fuori ambito ricevono un rifiuto
senza eseguire il nodo agente.

**Architettura:** il nuovo modulo `assistente/router.py` contiene schema, prompt, testo da
classificare e frase di rifiuto. `modello.py` costruisce il router con
`with_structured_output(json_schema, include_raw=True)`. `grafo.py` aggiunge i nodi `router` e
`rifiuto` e rinomina `modello` in `agente`. L'ambito arriva da `AMBITO_AGENTE`.

**Stack:** Python 3.14, LangGraph 1.2.17, langchain-openai 1.7.2, langchain-core 1.7.0, pytest
9.1.1. Nessuna dipendenza nuova: Pydantic arriva già con langchain-core.

**Specifica:** `docs/superpowers/specs/2026-11-14-router-design.md`

## Vincoli globali
- Si lavora solo dentro `lezione_4/`, sul branch `feat/agente-web`.
- Codice sincrono e moduli piccoli; nessuna dipendenza nuova.
- `AMBITO_AGENTE` è obbligatoria; se manca o è vuota → `ErroreConfigurazione` → uscita con codice 2.
- Categorie esatte: `conversazione`, `fuori_ambito`. Campi esatti: `categoria`, `motivo`.
- Nomi dei nodi esatti: `router`, `agente`, `rifiuto`, `strumenti`, `conferma_eliminazione`,
  `limite_raggiunto`.
- Righe di log esatte, che sono le evidenze:
  - `router: categoria=<c> motivo=<m> -> <agente|rifiuto>` (INFO);
  - `agente: chiamata al modello` (INFO);
  - `rifiuto: domanda fuori ambito, agente non eseguito` (INFO);
  - `router: output non valido (<errore>), la domanda passa all'agente` (WARNING).
- Fail-open: se l'output del router non è valido, la domanda va all'agente. Le eccezioni di rete
  invece si propagano.
- Router: ultimi 3 turni precedenti, ogni messaggio troncato a 300 caratteri, senza chiamate a
  strumenti e senza `ToolMessage`.
- I test automatici non usano LM Studio. Le prove reali stanno solo sotto `--lmstudio`.
- Commit in Conventional Commits in italiano, terminati da
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Prima di ogni commit: `git status`,
  controllo del diff, staging selettivo. **Nessun push**: dopo ogni commit scrivere «ho fatto il
  commit» e attendere.
- Comandi da PowerShell nella cartella `lezione_4/`, con `.\.venv\Scripts\python`.

## Punti da controllare in revisione
1. **Follow-up dopo un turno con strumenti:** la cronologia contiene `AIMessage` con `tool_calls`
   e `ToolMessage`. Il testo per il router deve includere solo domande e risposte finali, e la
   domanda corrente deve restare l'ultima (Task 2,
   `test_testo_esclude_strumenti_e_tiene_la_domanda_in_fondo`).
2. **LM Studio giù durante il router:** l'eccezione deve risalire fino alla CLI, che stampa
   `descrivi_errore`, e la cronologia della sessione non deve cambiare (Task 4,
   `test_errore_del_router_non_tocca_la_cronologia`).
3. **Conferma delle note dietro al router:** la ripresa con `Command(resume=...)` non deve
   rieseguire il router (Task 4, `test_conferma_note_non_riesegue_il_router`).
4. **Contenuto dei messaggi non stringa:** il testo per il router va letto con `.text`, che regge
   anche il contenuto a blocchi (Task 2, `test_testo_con_contenuto_a_blocchi`).
5. **Virgolette in `AMBITO_AGENTE`:** il caricatore PowerShell del README non toglie le virgolette,
   quindi in `.env.example` la riga va scritta senza virgolette. Va verificato nel Task 6 caricando
   `.env` con il comando del README e controllando che il rifiuto non mostri virgolette.
